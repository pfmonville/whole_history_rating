# Release 3.7.1 — full benchmark validation

Run on 30 September 2026. The complete documented protocol was executed:
three cross-library grids (223 validation configurations), three WHR deep
dives, and all six light/dark figures. The existing input files were reused;
the SHA-256 hashes in every result identify their exact contents.

The fitting/scoring source was commit `e8ff4f1756d3d43a50e5aa4758098cb8bd22af26`. Subsequent release
changes update generated artifacts, documentation and figure labels. The controlled baseline
is tag `v3.7.0`, source commit `d9944001ca219cc38b9e7de37921a1d46a58fb86`.

## Held-out predictive log-loss

Lower is better; these are test-season predictions, not the training
`log_likelihood()` diagnostic. Hyperparameters were selected on validation
seasons before test scoring. All selected grid optima are interior, except
axes explicitly recorded as flat.

| Dataset | Test games | WHR | KickScore | TrueSkill Through Time |
|---|---:|---:|---:|---:|
| NBA | 1,312 | 0.665980332 | 0.661976303 | 0.688239221 |
| Tennis | 2,816 | 0.613533300 | 0.605663520 | 0.604291203 |
| Football | 1,826 | 1.008488573 | 1.013435743 | 1.022831900 |

The selected WHR settings remain `w2=1000` for NBA, `w2=3` for tennis and
`w2=30` for football, with `account_for_uncertainty=True` on all three.
The rankings and rounded headline scores are unchanged.

## Controlled regression check: 3.7.0 versus 3.7.1

Both versions were fitted from scratch on identical input bytes, in the same
Python environment, using the same benchmark code and settings. The baseline
imports the `whr/` source archived from `v3.7.0`; source identity is checked
explicitly instead of relying on the shared environment's package metadata.

- At the selected settings, **every test prediction, player rating and
  uncertainty is exactly identical** across the three head-to-head datasets.
  Learned advantages, draw tendency, training log-posterior and test metrics
  are identical too. This covers 5,954 test games.
- All three deep dives were also rerun with the 3.7.0 source. Every numerical
  field in their result files is identical to 3.7.1, including NBA online
  evaluation and both full-history curve files. Only provenance differs.
- These checks establish no observed regression on this protocol. They do not
  imply that every possible input or future season has been covered. The
  persistence and invalid-input fixes have separate unit regression tests.

The 3.7.0 correction to `log_likelihood()` is retained: game log-probabilities
are counted once, plus the player priors. Changing that diagnostic did not
rescale held-out predictive log-loss.

## Convergence

Every audited WHR `auto_iterate` call returned `converged=True`, with its
measured gradient norm below the requested threshold. No call stopped because
of its wall-clock limit. This also holds for the controlled baseline reruns.

| 3.7.1 run | Automatic fits | Largest final gradient norm | Requested threshold |
|---|---:|---:|---:|
| `versus_nba` | 5 | 0.000974559 | 0.001 |
| `versus_tennis` | 6 | 0.000989074 | 0.001 |
| `versus_football` | 8 | 0.00099353 | 0.001 |
| `nba` | 8 | 0.00406173 | 0.005 |
| `tennis` | 6 | 0.004818 | 0.005 |
| `football` | 6 | 0.00158425 | 0.003 |

NBA's online updates retain the original protocol of six `iterate` sweeps per
time bin, after scoring that bin; they do not claim per-bin convergence.
KickScore and TTT retain their existing iteration budgets (`max_iter=100` and
`convergence(epsilon=1e-3, iterations=10)`). The convergence audit above is
specific to WHR, not a claim that every competitor fit reached its own tolerance.

The tennis logs include `DisconnectedPlayersWarning` for comparisons without
a training-history connection, including cold starts. Those observations remain
in the evaluation and use the library prior, as documented in the protocol;
every model is checked to score the full test set.

## Changes from the previously committed artifacts

The historical JSON files were not all generated by 3.7.0. In particular, the
WHR deep-dive results still pointed to commit `7441cf8` (version 3.0.0), and their
original runtime versions and input hashes were not recorded. Earlier changes
to the advantage estimator and convergence-check batch size therefore belong
in this historical comparison, not in a claimed 3.7.1 regression. The controlled
comparison above holds code-independent factors fixed and gives exact equality.

| Historical artifact / model | Previous log-loss | 3.7.1 log-loss | Delta | Accuracy |
|---|---:|---:|---:|---:|
| nba / `whr_plain` | 0.683943789 | 0.683950579 | +0.000006790 | 60.290% → 60.290% |
| nba / `whr_home_frozen` | 0.669892240 | 0.669899130 | +0.000006890 | 63.643% → 63.643% |
| nba / `whr_home_online` | 0.634279176 | 0.634279760 | +0.000000584 | 64.253% → 64.253% |
| tennis / `whr` | 0.616440692 | 0.616305610 | -0.000135082 | 66.974% → 66.974% |
| football / `whr_bt_constdraw` | 1.013241775 | 1.013175151 | -0.000066625 | 51.698% → 51.643% |

The full machine-readable record includes deltas for every model, including the

rounded headline score is unchanged. In particular, football's constant-draw
ablation now rounds to 51.6% accuracy; its Davidson deep dive rounds to 51.4%.

## Environment and reproducibility

Python 3.13.13 on macOS arm64; WHR 3.7.1, NumPy 2.4.4, pandas 3.0.6,
KickScore 0.2.0, TrueSkillThroughTime 1.1.0, SciPy 1.18.1, Numba 0.68.0,
llvmlite 0.50.0 and Matplotlib 3.11.2. The complete installed environment is
recorded in the validation JSON and pinned requirements below.

`PYTHONHASHSEED=0`; `OPENBLAS_NUM_THREADS`, `OMP_NUM_THREADS`,
`VECLIB_MAXIMUM_THREADS` and `NUMBA_NUM_THREADS` were each set to `1`.
Independent runs executed concurrently, so their elapsed times must **not** be
used as a speed comparison between models or releases.

To recreate the environment from the release checkout:

```bash
uv venv .venv-benchmark --python 3.13.13
uv pip install --python .venv-benchmark/bin/python \
  -r benchmarks/results/release_3.7.1_requirements.txt -e .
export PYTHONHASHSEED=0 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export VECLIB_MAXIMUM_THREADS=1 NUMBA_NUM_THREADS=1
```

Run the six scripts listed in the [benchmark README](README.md) using that
interpreter, then `benchmarks/make_figures.py`. Check downloaded input hashes
against the committed JSON before treating a later rerun as identical-data
reproduction. The release evidence archive includes the audit wrappers and
raw comparison records used for this run.
